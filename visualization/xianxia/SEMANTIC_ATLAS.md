# 修仙数学地图：语义与物件图鉴契约

本目录是 `research/graph.json` 的**表现层**。数学身份、定义域、量词、证据层和合取关系仍以规范正文、Claim 总账与图数据为准；地形、建筑大小和装饰不构成数学判断。图可以持续增长，旧节点的身份和定位必须保持可找回。

## 世界的共同画风

一个有地图感的水墨像素修仙世界：青黛山体、玉青湖海、赭色古道、暖金灯火；俯视斜角，清晰轮廓和少量细腻动画。古代仙门建筑、灵植、法器、云海、山门、渡口和阵法属于同一世界。不要用互不相干的现代城市、史诗写实照片或通用 emoji 拼贴。远景保留大片负空间；放大后才显示细物件、标签与条件线。

物件的**角色**与**造型变体**分两层：角色告诉读者它是定义、命题、反例、开放门槛、例子或合取关系；同一角色可有多个外观。变体由稳定的节点 ID、区域与主题版本确定，不通过每次加载重新抽签。手工覆盖只改变造型或位置；改变数学身份须同时更新规范来源。

## 物件语法

| 数学角色 | 主体物件 | 至少可轮换的修仙形象 | 视觉必须传达的动作 |
| --- | --- | --- | --- |
| 定义、记号、约定 | 立碑 | 界碑、玉简碑、刻符石门、藏经阁入口 | 点击看到精确定义与适用域 |
| 引理、证明工具 | 修习台 | 竹简台、炼器炉、观星台、法尺、阵纹石盘 | 从这里可追溯输入及推导 |
| 已有自足推导的命题 | 研修据点 | 山亭、书院、灯塔、渡口、药庐、洞府 | 展示明确证据状态；建筑本身不暗示外部定理已验证 |
| 候选命题 | 待修楼阁 | 云中楼、未封顶的观台、半开的卷轴殿 | 详情醒目标明 candidate 与未闭 proof obligation |
| 来源报告、待复核条目 | 残卷库 | 封箱经卷、旧石刻、密封藏书匣 | 只能进入来源身份，不借建筑暗示可靠性 |
| 开放问题或探索空间 | 未探地貌 | 云海、深湖、雪峰、秘境入口、远山 | 同一“有潜力”可有多种景观，潜力是编辑标签而非自动真值 |
| 明确障碍、反例 | 断路与关隘 | 断桥、封山阵、坍塌栈道、裂隙、禁制木桩、残碑 | 一点即可读到**阻断哪条精确推理**与反例范围 |
| 例子与校准对象 | 灵物与试炼地 | 灵兽、灵植、炼丹釜、试剑石、棋台、水镜 | 显示完整对象及其参数、残差和局部/全局范围 |
| 算法或可复现实验 | 机关房 | 算筹台、观测阵、卜算盘、符箓机关 | 入口关联代码、参数、seed、精度与证据边界 |
| 文献事实 | 典籍馆 | 经楼、外来卷宗、碑拓、校勘台 | 引用一手精确位置，与本库解释分层 |
| 合取超边 | 法阵枢纽 | 多符阵眼、汇流阵盘、祭坛、河流汇口 | 每个输入进入同一 ∧ 阵眼，再从阵眼到输出；不可画成单输入蕴含 |
| 等价、限制、反驳等关系 | 有类型的道路 | 双向虹桥、山口边界、断裂禁制、未通云路 | 颜色/线型和文字均区分 relation；路线本身不可替代 scope 与 status |

每类至少做三种**可识别的轮廓**，优先改屋顶、石材、边缘饰物与位置关系，而非只换色。大山、大海、湖泊是区域地貌，不能自动代表命题真伪或严谨程度；人可手工为某个经说明的研究前沿选择景观。图例必须明确物件是导航隐喻。

## 主题地貌与精确身份

| 数学主题 | 地貌方向 | 适合的局部物件与路线隐喻 |
| --- | --- | --- |
| 定义与参数字典 | 中央宗门山麓 | 界碑、玉简、阶梯、山门，通向其他主题 |
| 局部 RLEB 与路径动力 | 层叠山道 | 递进台阶、留域关口、锚点灯笼、断路 |
| 全局结构与纤维 | 高山与洞天 | 双向影子峰、纤维洞窟、值域观台、固定点泉 |
| 算子空间规模 | 云海与大洋 | 母空间海图、量尺灯塔、未定航道、proper 岛 |
| 有限数据与局部值域 | 阵法平原 | 样本阵眼、整窗法阵、collar 城墙、拓扑关口 |
| 锥与复合正则性 | 峡谷与灵药谷 | 冻结面石壁、乘子锁、药庐、秩亏裂谷 |
| Markov、随机近端 | 水乡与群岛 | 耦合渡口、不同表示的分汊水道、律空间舟 |
| 规范例库 | 试炼群峰 | 每个完整图独立试剑台，近邻同构对象有标示的桥 |

这些只是初始区域定位。一个命题可以跨主题，跨域超边仍须在详情中呈现全部输入；空间邻近只提升检索效率，不构成蕴含。上表涉及未审、候选或开放区域时不可凭景观把状态升级。

## 用真实图节点校准物件

| 图中 ID | 可用形象 | 必须保留的数学读法 |
| --- | --- | --- |
| `D01`, `D02`, `D03` | 三块不同形状的开宗界碑 | `E01` 的两项输入共同进入等价阵眼，同一图块、步长和对距 |
| `COV`, `CMP`, `LOC` | 渡口、收缩法尺、留域关隘 | 三个独立前提，不能由 `D02` 的全对 RL 自动出现 |
| `R02` | 局部山亭 | 局部 PPA 有限长度，完整 resolvent 另需纤维同一性 |
| `H02` | 待修云台与候选旗 | 图中标明 candidate，不能画成已经封顶的定理大殿 |
| `E19` 的输出 `SIZE` | 尚未定航线的广海 | 总体大小比较是开放目标，入海要共同母空间与量尺 |
| `E30` | 指向 `STOCH-LIMIT` 的坍塌栈道 | 反例阻断给定度量未完备时的路径极限推理；不阻断所有随机定理 |
| `E42` | 二输入的双符阵盘 | 固定边缘二进制条件残差的等价，不能接到 Gaussian 或同步 OT 残差 |
| `E100` | 错位零锚的破桥 | 全对图块与 coverage 仍缺完整零集保距离；点击读完整反例 |
| `E133` | 会收缩却缺全对 RL 的试炼门 | 动力证书不能逆推整个完整图的全对模 |

这是艺术和精确逻辑同时检查的样例集；其余节点沿同一图数据的字段与规范锚点扩充。`E..` 是关系，不是新的 Claim；关系阵眼的全部输入、输出和范围都须可检索。

## 增长与布局不变量

1. **先语义、后空间、再装饰。** 读图中的原始 ID、输入、输出、关系、scope、status 和规范链接；给节点分配主题与物件角色；最后选择变体和地形。每一步留独立数据层。
2. **稳定坐标。** 首次布局为每个节点及超边阵眼记录持久坐标、区域、资产变体与规则版本。重排输入 JSON 或加入新节点后，已有 ID 不迁移。若确需整域改造，显式版本迁移与旧位置跳转，绝不静默改变。
3. **增量扩地。** 新节点优先落在相关主题、依赖邻居附近的保留空位；没有合适位置就打开相邻区块。给路径与文字留碰撞缓冲。手工置入的地标权重大于自动位置。新关系可以新建阵眼与道路，不需要搬旧建筑。
4. **随机可重复。** 世界 seed、区块坐标、稳定 ID 与资产版本共同决定装饰；相同输入得相同输出。装饰噪声和物件变体不依赖节点数组顺序。未读的区块可按需生成，生成后应固定其关键路径与地标。
5. **有约束的自然感。** 先固定主题邻接、山脊/水岸、渡口和跨域路线，再对区块地表分层生成噪声与植被。最后检查断路、重叠、视野遮挡、不可达与标签冲突；失败时在局部换候选，不全图洗牌。
6. **双重真实。** 地图图像和搜索/详情都从同一图快照产生；所有 294 个现有节点与 194 条超边必须可检索。每条输入合取、relation、scope、status 与规范链接逐字保留；图像角色不得覆盖证据字段。
7. **可读性层级。** 全局缩放显示区域与前沿；中景显示物件类别和选中路线；近景才显示每个节点、合取阵眼和装饰。键盘搜索可直达任一节点，不能因“未发现的迷雾”藏掉研究资产。

对游戏生成技术的参考是“有约束的空间数据 → 带 seed 的点与属性 → 分区/分层生成 → 验证”。这是对本项目的设计选择，不声称商业游戏都采用同一种算法。参见 [Unreal PCG Overview](https://dev.epicgames.com/documentation/unreal-engine/procedural-content-generation-overview)、[Generation Modes](https://dev.epicgames.com/documentation/en-us/unreal-engine/using-pcg-generation-modes-in-unreal-engine) 与 [PCG Data Types](https://dev.epicgames.com/documentation/en-us/unreal-engine/procedural-content-generation-framework-data-types-reference-in-unreal-engine)。

## 给下一轮创作的入口

- 新命题先进入规范正文与 `research/graph.json`，表现层只消费它，不从物件逆写数学命题。
- 新增可复用形象先登记角色、至少三个变体、图例和缩放级别；素材文件保留源文件与导出文件。
- 新区域先固定主题边界、相关旧节点及保留通路；增量测试比较新旧布局 manifest，证明未被编辑的 ID 坐标不变。
- 每次改图运行全节点/超边保真与键盘可达测试，并进行真实浏览器截图及近、中、远三个缩放级的视觉审查。
