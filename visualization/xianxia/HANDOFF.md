# 下一轮接续：云岫修仙可视化

## 目标与当前方向

用户满意原图的检索/缩放/详情功能，但嫌物件粗糙单一。要求先设计可识别的物件，再组织协调的整体山海；同一数学角色允许多种造型；未来图增长必须保持旧位置可找。前端设计与实现由 Astra 负责。

第一批系统有 32 个可编辑 SVG、独立图鉴、持久布局与增长测试。初版离线地图为 294 节点/194 超边；该阶段曾从权威图重建为 326 节点/214 超边；现行数量由 `research/graph.json` 和重新生成的页面确定。规范研究资料和原地图保持原位。

## 已做的选择

- 青绿山水、暖金器物、古代修仙建筑，同一画布与地面锚点。
- 使用代码原生 SVG；没有声称使用 ImageGen，没有依赖未保存的生成图或裁切坐标。
- `village/mine/mountain/barrier` 是继承旧交互层的内部家族键；界面明确改为“书院/灵物/秘境/禁制”。**mine 不表示已证资源。** 默认研究节点为中性灵物，不从缺失证据字段推定证明等级。
- 明确 candidate 节点显示“候”；source-report 显示“源”；open 输出“问”；refutes 输出“驳”。具体被阻断的方向仍在超边详情，不把全部关联领域标为失败。
- 位置与语义分离：状态更新可换合适的物件家族，但不会移动节点。
- 全量路线默认关闭，选择节点/关系会显示对应完整超边；可显式打开所有路线。
- 新主题内容的外山按预留南向区块扩展，地貌不是力导布局，每次加点不摇动全图。

## 验证记录

运行 `python3 -m unittest discover -s visualization/xianxia/tests -v`、`node --check visualization/xianxia/src/map.js` 和 `node visualization/xianxia/tests/test_runtime.js`。后者按当前权威图动态核全部节点和超边详情、搜索、区域定位与缩放；这不代表浏览器排版/触控已验证。125 个新节点/超边的合成增长测试验证旧节点与阵眼全部固定。旧世界的节点与阵眼坐标由持久清单保留。

真实浏览器拒绝 loopback 和 file URL，且禁止更换浏览器表面绕过。只允许静态源文件、数据和独立素材渲染检视；**未完成真实浏览器整页目测**。下一轮如环境允许，需在远、中、近三种缩放和窄屏下实际检查。

## 下一批具体工作

1. **用户逐件画风验收**：先打开 `gallery.html`，收集最喜欢/最不喜欢的物件 ID。当前造型是精炼二维矢量仙侠物件，可继续打磨材质细节；还不是完整独立游戏的最终美术。
2. **更多角色专属资产**：定义碑、代码机关、文献残卷、候选未封顶云台，各至少三种真正不同的轮廓。现有四组 8 变体是首批通用表现，不声称所有语义细分各有三种。
3. **灵兽与生活性装饰**：鹤、鹿、狐狸、灯笼、船桥、荷叶、风铃等要先入图鉴，不让装饰抢占真实数学节点点击区域。
4. **更自然的岸线/山脉**：当前地貌是确定性椭圆主题岛+坐标噪声。下一版可增加共同流域、等高线、连续山脊和装饰桥；需保持旧地标落点和阅读空间。
5. **真正游戏化的运动**：目前 WASD 是探索者漫游，不是可碰撞角色控制器，没有战斗、背包、存档剧情。加角色动画前先固定足点、遮挡顺序与 reduced-motion。
6. **复杂增长**：当前新增岛屿边界扩展会改变“全图”缩放，但旧坐标不变。视口可跨会话恢复、按需地块生成、世界版本迁移工具仍待实现。
7. **绘制性能**：初版一次生成整片 terrain Canvas。若扩至数千节点，改为按视口加载地块；保持 seed 和 manifest，不能借优化打乱世界。
8. **增强类型规范**：当前节点证据字段只有少数显式存在；若以后规范图补齐类型/状态，应从真正字段驱动物件角色，不靠文字关键词臆测等级。

## 必须保持

完整合取输入、relation、scope、status、规范链接；所有节点和超边可由键盘目录到达；地貌不表示价值排名或证明；候选不因美术升级变成定理；旧世界定位不静默重排。重新生成后提交源码、SVG、catalog、world、HTML 与测试，不只提交截图。
