# 宇宙研究图：数学语义与动态验收契约

这是一份从 `research/graph.json` 生成的**研究导航**设计约束；数学真值仍以规范正文和 `CLAIMS.md` 为准。画面不能因为一个对象被画成恒星、行星、卫星、飞船或黑洞，就给它增加证明状态、重要性或天文学上的物理身份。

## 天体层级

| 画面 | 数学身份 | 必须守住的边界 |
| --- | --- | --- |
| 太阳系整体 | RLEB–PPA 的局部收敛定理链 | 系统整体不是一个额外的图节点，也不能取代真正超边。 |
| 中心恒星 | `R02`：局部 PPA 有限长度 | 只有 `R01 ∧ CMP ∧ LOC` 在 `E03` 指定范围内指向它；候选状态按数据文字显示。 |
| 八个主轨道入口 | `D01,D02,D03,D04,COV,CMP,LOC,R01` | 行星是可点开的原图节点。轨道半径和公转周期只是视觉导航，不表示逻辑强弱、物理时间或证明顺序。 |
| 卫星、小天体 | 被明确关联的其他真实节点 | 每个可点击物件必须显示其图 ID、准确正文链接和关联缘由。装饰性粒子不得冒充数学对象。 |
| 其他恒星系 | Markov、结构、算子空间、锥、有限数据等独立主线 | 各自保留对象、残差、状态及完整输入条件；尤其二进制刷新与 Gaussian Gibbs 不合成同一个定理。 |
| 未知星系 | 仍开放的方向，如 `SIZE` | 未知是研究状态的说明，不等于该方向永远不可解。 |
| 人造航道和探测器 | 原图超边及其阅读路径 | 多输入必须汇入**一个合取枢纽**再到输出；`limits`、`refutes` 不是正向证明箭头。飞船飞行是阅读引导动画，不是算法迭代、概率动力或数学蕴含。 |

太阳系的两条承重路线须能在页面上直接检查：`E02: D02 ∧ COV ∧ D04 → R01`，`E03: R01 ∧ CMP ∧ LOC → R02`。`D01` 与 `D03` 是表示和对象入口，不应画成 `E02/E03` 的额外前提。八个入口是页面组织方式，不是“八个必要条件”的声明。

## 动态布局与公转

1. 将**语义锚点**与**渲染位置**分开。力导向布局处理星系/节点的可读排布，碰撞力处理星体及标签的近距重叠；已有图 ID 的持久锚点在增量导入时不能全部洗牌。
2. 恒星、行星和卫星应有可见、不同周期的公转；轨迹应以各自父对象为中心，至少在太阳系放大视角可观察。用户可暂停、降低运动，系统应尊重 `prefers-reduced-motion`。
3. 轨道动画不能改变超边的端点身份。边从真实渲染位置更新，或从稳定锚点绘出并明确标识；不得因一帧交叉把 `A ∧ B → C` 看成 `A → B → C`。
4. 缩放时采用层级揭示：总览显示星系和主要星系间联系；近看显示主星、行星、卫星、阵点和探测器。搜索、聚焦、悬停、点击必须能到达全部 294 个当前节点和 194 条当前关系，今后按真实数据自动增长。
5. 图数据增加时，仅凭稳定 ID、主题联系和当前邻域放置新节点；若局部无空间，扩张可用范围并局部松弛。不得为了布局伪造研究节点、超边或证明状态。演示增长所用虚构数据只能在隔离的演示态，不能保存进规范图。

## 视觉与可用性验收

- 画面应呈现连续的深空、恒星发光、行星体积/明暗、轨道层级及尺度远近，而不只是旧版图标换背景。它是**科幻研究宇宙**，不声称真实太阳系的天体大小和轨道周期。
- 每个真正图节点有原始 ID、摘要/标题、正文入口；每个超边有全部输入、输出、关系类型、scope 和 status。视觉状态从这些字段取得，不能由星体种类推断。
- 可拖动/缩放/搜索/暂停运动；放大时能够读清太阳系核心链及至少一条跨星系链。支持键盘打开详情和移动设备的基本点按。繁星和航船不得遮挡信息面板。
- 回归检查至少覆盖图数据一一对应、合取方向、局部增长时旧节点漂移界、节点碰撞、公转确实随时间变化且可暂停、减少运动、真实浏览器的宽窄屏截图和交互。

## 引擎边界

Obsidian 的交互感是参考，项目应使用可审查的开源图引擎/力学库及其许可，而不是把 Obsidian 的闭源前端复制进仓库。`d3-force` 的 simulation、link、many-body、collision 可承担图排布；Canvas/SVG/WebGL 负责渲染，取舍以 294/194 的真实数据和浏览器帧率验证。物理引擎只能帮助排布，数学超边的合取方向必须由本项目的数据适配层保证。
